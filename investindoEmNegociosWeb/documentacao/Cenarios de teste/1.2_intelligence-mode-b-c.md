# 1.2 - IntelligenceMode (B ou C)

## Objetivo
Garantir que o modo de inteligência do usuário (`B` ou `C`) seja salvo, retornado pela API e refletido corretamente nas telas de onboarding e perfil.

## Pré-condições
- Usuário autenticado.
- Endpoint de perfil disponível (`GET/PUT /api/v1/profile`).
- Frontend com telas `/onboarding` e `Configurações > Perfil`.

## Cenários de sucesso
1. Salvar modo `B` no onboarding
- Passos:
  - Acessar passo 1 do onboarding.
  - Selecionar modo `B`.
  - Preencher formulário e salvar.
- Resultado esperado:
  - `PUT /profile` enviado com `intelligenceMode = "B"`.
  - `GET /profile` retorna `intelligenceMode = "B"`.

2. Alterar para modo `C` na tela de perfil
- Passos:
  - Acessar tela de perfil.
  - Trocar modo para `C`.
  - Salvar perfil.
- Resultado esperado:
  - Persistência realizada.
  - Reabrir tela mantém valor `C`.

## Cenários de exceção
1. Rejeitar valor inválido no backend
- Passos:
  - Enviar `PUT /profile` com `intelligenceMode = "X"`.
- Resultado esperado:
  - API retorna `400`.
  - Mensagem: modo de inteligência inválido (aceita somente `B` ou `C`).
  - Nenhuma alteração persistida.

2. Rejeitar valor vazio no backend
- Passos:
  - Enviar `PUT /profile` com `intelligenceMode = ""`.
- Resultado esperado:
  - API retorna `400` por validação.
  - Nenhuma alteração persistida.

## Cenário de regressão
1. Dados antigos de perfil continuam funcionando
- Passos:
  - Carregar usuário já existente sem alteração manual de modo.
  - Abrir onboarding/perfil e salvar sem mexer no modo.
- Resultado esperado:
  - Sistema aplica valor padrão válido (`B`) quando necessário.
  - Demais campos do perfil permanecem íntegros (nome, CPF, telefone, objetivo financeiro).

## Critérios de aceite
- [ ] Apenas `B` e `C` são aceitos no backend.
- [ ] Onboarding salva e recarrega corretamente o modo selecionado.
- [ ] Tela de perfil permite editar e persistir o modo.
- [ ] Cenários de exceção validados.
- [ ] Cenário de regressão validado.
