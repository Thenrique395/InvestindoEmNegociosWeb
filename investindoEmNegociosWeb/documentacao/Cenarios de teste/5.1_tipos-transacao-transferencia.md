# Cenários de teste - 5.1 Tipos de transação (com transferência)

## Objetivo
Validar transferência formal entre contas com lançamento duplo no ledger:
- débito na origem
- crédito no destino

## Pré-condições
- Usuário com acesso a `Contas` (não Basic para gestão manual).
- Duas contas ativas.

## Cenários de sucesso
1. **Transferência simples**
- Ação: `POST /api/v1/accounts/transfers`
```json
{
  "fromAccountId": "<contaA>",
  "toAccountId": "<contaB>",
  "amount": 250.00,
  "description": "Reserva mensal"
}
```
- Esperado:
  - retorno `200`.
  - `transferId` retornado.
  - extrato da conta A com `Debit` e `SourceType=AccountTransfer`.
  - extrato da conta B com `Credit` e `SourceType=AccountTransfer`.
  - ambos com mesmo `SourceId` (`transferId`).

2. **Reflexo de saldo**
- Ação: consultar saldos das duas contas após transferência.
- Esperado:
  - origem reduzida em `amount`.
  - destino acrescido em `amount`.

3. **UI de Contas**
- Ação: executar transferência pela tela `Contas`.
- Esperado:
  - operação concluída.
  - listas/saldos recarregados.
  - extrato mostra origem como `Transferência`.

## Cenários de exceção
1. **Mesmo ID em origem e destino**
- Esperado: `400`.

2. **Valor <= 0**
- Esperado: `400`.

3. **Conta inexistente**
- Esperado: `404`.

4. **Conta inativa**
- Esperado: `400`.

5. **Apenas uma conta ativa**
- Na UI: bloquear fluxo e exibir orientação.

## Regressão rápida
- Pagamento/recebimento de parcelas continua gerando `InstallmentPayment`.
- Estorno de pagamento continua gerando `InstallmentPaymentReversal`.
- Transferência não afeta status de parcela/plano.
